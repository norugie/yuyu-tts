# CLAUDE.md — YuyuTTS working rules

Claude Code loads this file automatically at the start of every session. It holds the rules for how we work on this project. How the bot is built lives in `ARCHITECTURE.md`.

## Project in one paragraph

YuyuTTS is a self-hosted Discord bot that reads a mute friend's text messages aloud in our voice channel, fast enough for live game comms, using cute anime-style voice presets. It runs on Youmu's Windows PC (RTX 4070) with Docker Desktop (WSL2): a Node/TypeScript bot container (discord.js + @discordjs/voice with DAVE) and a Kokoro-FastAPI GPU container. It only runs while Youmu is online.

## Commands

- `npm test` (unit tests) and `npm run typecheck`. Run both before saying a change is done.
- `npm run test:int`: integration tests (need ffmpeg; some need Kokoro running).
- `docker compose up -d --build` starts everything; `docker compose logs -f bot` shows the bot's logs.

## How we work

- For anything bigger than a small fix, write a short plan first (files to touch, approach, how it will be verified) and wait for Youmu's OK.
- Make the smallest change that does the job, then verify it and show how.
- If the code and `ARCHITECTURE.md` disagree, stop and ask which one is right. Then fix the other one.

## Verify, don't assume

- Check current docs for **discord.js**, **@discordjs/voice**, and **Kokoro-FastAPI** before using an API. Many older Discord voice tutorials are broken since DAVE (end-to-end encryption) became mandatory on 2026-03-01.
- Prefer the official docs and the library's own source/README over blog posts.
- When you rely on a version number or API shape, say where you checked it.
- After installing or changing voice dependencies, check `generateDependencyReport()` from `@discordjs/voice` inside the container and confirm a DAVE library is listed.

## Coding style

- TypeScript in `strict` mode. No `any` unless there's a comment explaining why.
- Small modules with one job each (e.g. normalization, TTS client, queue, voice, settings). Pure functions where possible, so they're easy to unit test.
- Config comes from environment variables, validated once at startup. Fail fast with a clear message if something is missing.
- Errors: never crash the bot on one bad message. Log it, skip it, keep going.
- Logs are short and useful: what happened, which message/user id, how long it took. Never log the bot token.
- Tests live in `tests/`, mirroring `src/`; every normalization rule has a test.
- Follow the folder structure in `ARCHITECTURE.md`. Changing it is an architecture change and needs approval.
- No speculative architecture, and no new dependency without saying why it's needed and what the smaller alternative was.
- Fix root causes, not symptoms. If a workaround is unavoidable, say so.

## Never

- Never commit the bot token, `.env`, or any secret. `.env` stays in `.gitignore`; keep a `.env.example` with empty values instead.
- Never add paid APIs or paid services.
- Never add LLMs or Ollama. This project is TTS only.
- Never use voice models cloned from real people or from existing characters. Only use models whose license and training data are clearly stated and allow this use.
- Never say something works without verifying it, and showing how it was verified.
- Never make large refactors that weren't asked for.
- Never run git commands that change history or the remote: no commit, push, merge, or opening/editing PRs. Youmu does all of that from their local clone. Claude only edits files in the working tree and says what changed.
- Never change anything outside the repo without asking first.
